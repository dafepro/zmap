02 / How a session works

Three layers. Two kinds of authority.

In the player’s browser
Zoomigo route + adapterEnter / exit, approved appearance, UI, controls
→
Zoomap clientCamera, input, prediction, render loop, shared state
Avatar runtime + approved assetsPrepared character factory, fitting, poses, held gear
→
Character presentationAccepted world state becomes motion and effects
Trusted service boundary · WebSocket / app-issued credentials
zmap room serviceAuthenticate, access checks, relay, host lease + epoch
→
Zoomigo adapters + databaseMembership, entitlements, atomic saved edits + receipts

Transient world authority

One eligible browser simulates the room at 30 Hz. It publishes checkpoints at 15 Hz; clients interpolate display frames and predict local movement. The relay fences host changes with epochs. Hidden or stalled hosts yield; an empty room runs no world simulation.

This is browser-hosted simulation with a WebSocket relay—not an always-running server physics loop or a peer mesh.

Durable product authority

Zoomigo’s trusted store checks ownership, current entitlement, placement, revision and idempotency before saving a layout. A browser host can influence transient play; it cannot grant inventory, training credit, team access or rewards.

Deploy one writer per room. Distributed ownership and a production database adapter are not supplied by the reference service.

04 / Characters are their own system

Author once. Assemble through contracts.

“Avatar builder” means three related things—not a dependency on the studio’s whole website.

The runtime

avatar-studio/src/ validates recipes, loads verified assets, assembles skinned components, fits accessories, animates the rig and owns exact hand grips. No accounts, room transport or UI renderer.

The design studio

avatar-studio/app/ is a separate browser consumer: customization, body build, views, equipment inspection, look JSON and portrait export. Current saved looks are browser-local; Zoomigo must persist approved recipes.

The source asset kit

avatar-studio/assets/source/ holds editable Blender files, generators and reference material. public/ holds the versioned runtime catalogs and GLBs.

Compatibility is a contract

Fixed-height body builds grow tissue around limb centerlines. Shared sockets and bind frames align clothes and equipment. Accessories declare fitting and selective hair interaction; glasses arms can disappear into hair without carving a surrounding hole.

One hat does not require a separately modeled variant of every hairstyle. But arbitrary meshes are not automatically compatible: author correct pivots, fit volumes, rig weights and anchors, then qualify combinations.

Current presentation: angular cel/ink rendering, reference-based walking and running, five emotes, draw/stow and left/right/shared grips. The 16-view export is a fixed-pose atlas—not an animated sprite system.

Content workflow

Concept reference → front / side / top studies → interactive Blender modeling → named parts and anchors → verified GLB/catalog export → actual browser inspection → fit, motion and resource tests.

Retain source and provenance. Validate the in-engine result, not only the Blender render.
05 / Connect the pieces

The adapter is intentionally small.
The responsibilities are explicit. 

// Browser contract outline—not a complete app.
import { Zoomap } from 'zmap';
import { AvatarLibrary } from '@zmap/avatar-studio';

const library = new AvatarLibrary(catalog, assetBase);
const createAvatar = await library.prepare(approvedRecipe);
const world = new Zoomap({
  container, map, catalog: worldItemTypes,
  visuals: {
    character: () => createAvatar().asCharacter()
  }
});
await world.enter({
  url: relayUrl,
  room: teamRoomId,
  credential: issueFreshRoomCredential
});
// On route exit, release both owners:
world.dispose();
library.dispose();
This single-look outline demonstrates the seam. A real adapter resolves each roster identity to its approved recipe and connects equipment, performance and scenery presentation. See examples/models.ts and examples/action-models.ts.

Approve and preload

Resolve app-owned appearance keys into validated recipes. Serve versioned catalog/GLB assets from your own static path. Prepare factories before the synchronous character hook is called.

Join with real access

Mint fresh credentials for the requested team room. The relay delegates authentication and continuing access checks to trusted app adapters. Replace every demo identity and token.

Render accepted activity

Pass avatar-facing velocity and accepted presentation time into animation. Keep gameplay consequences in shared simulation; use avatar and scenery hooks for display.

Save and release correctly

Commit edits transactionally. Keep stable retry IDs for unknown outcomes. On route exit, dispose the world and owned character/asset resources. Training routes should not load game code.

Packaging today: both packages have built v0.1.1 GitHub Release tarballs. Avatar Studio now lives in dafepro/zmap-avatar-studio, with independent history and CI. The avatar-studio/ directory in zmap is a pinned development submodule. Zoomigo installs release packages without the submodule. Use one Three.js copy and deploy matching client, relay and catalogs. See installation instructions.

Performance and operations boundaries

The proposed release matrix includes 20 distinct avatars, 50 placements with five active complex toys, 15-minute phone runs, cold/warm entry, transport-level impairment, recovery distributions and measured cost. Existing desktop and message-shaped tests cover only part of that matrix. Distributed relay ownership, graphics-context recovery and database unknown-outcome handling remain explicit follow-ups.

What “independent v3” changes

Build a new lounge with its own versioned room state. No conversion of alpha Canvas maps, coordinates or placements is required. Keep unrelated Zoomigo accounts and training intact. Historical migration instructions in the original brief are superseded by this scope. A pilot can be disabled without introducing Canvas fallback or concurrent writers to the same room.
