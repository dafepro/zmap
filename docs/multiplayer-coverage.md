# Multiplayer requirements and measured coverage

The functional multiplayer paths have automated coverage. The entire nonfunctional target matrix in `specs.md` is **not yet qualified**. Passing a local browser test is not a physical-phone or WAN percentile claim.

| Requirement boundary                               | Automated evidence                                                                                                     | Remaining qualification                                                                                             |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Join, identity, late join, authority fencing       | Real WebSocket service tests; independent browser clients observe membership and shared motion                         | Production authentication integration                                                                               |
| Abrupt host loss and silent host                   | Browser host close, coordinator lease expiry, old-authority rejection                                                  | Repeated recovery distribution on baseline devices                                                                  |
| Shared toy and durable edits                       | Browser kicks, convergence, placement/move/removal, ownership, revision CAS, restart                                   | Full-room varied interactions over long runs                                                                        |
| Lost receipt and reconnect                         | Impaired-network test loses saved receipt and drops connection; retries same command; exactly one committed revision   | Broader faults and long disconnects                                                                                 |
| 20 connected avatars                               | Real service accepts 20 distinct sockets and rejects the 21st                                                          | 20 rendered, distinct avatars on baseline phone                                                                     |
| 150 ms RTT, jitter, 2% loss target                 | Three rendered browsers behind ordered WebSocket message proxy: 75 ms each direction ±15 ms; drops every 50th snapshot | This is application-message loss, not packet loss/TCP retransmission; run transport shaping separately              |
| Host recovery ≤5 s p95                             | Test gates each sampled recovery at 5 seconds; writes actual sample                                                    | Single run is not p95; repeat with documented sample count                                                          |
| Local response ≤100 ms p95                         | Browser keyboard movement observed; coarse automation timing recorded                                                  | Input-to-visible-frame instrumentation on baseline device; current polling sample is not a gate for this percentile |
| Cold ≤6 s / warm ≤2 s p95, critical download ≤4 MB | Existing desktop entry/resource sample; bounded avatar catalog and assets                                              | Repeated cold/warm runs at specified 10/2 Mbps, 80 ms RTT                                                           |
| Frame time ≤33.3 ms p95, 15-minute full room       | Desktop sample; studio 40 replacement cycles and repeated shader toggles retain bounded live GPU resources             | Named physical phone, 20 avatars, 50 placements including five active complex toys, thermal/stall report            |
| Cleanup and independent rooms                      | Repeated enter/leave browser checks; asynchronous auth/store isolation and concurrent room limits                      | Extended mobile lifecycle, tab suspension and soak                                                                  |

Run `npm test` for service, protocol, persistence and simulation tests, then `npm run test:e2e` for real browser journeys. The network test is `tests/browser/network.spec.ts`, using `tests/helpers/network-proxy.ts`; its latest sample is `docs/evidence/network-sample.json`. Browser tests use ports 5174/8788 and disposable test-room data, independently of the user's live 5173 session.

Avatar Studio has its own unit, browser and package-consumer tests. The hub now uses its prepared factories, so the root browser suite also exercises that integration. Both suites run in CI. CI on a desktop runner is useful regression evidence, not a substitute for the remaining device and full-room matrix above.
