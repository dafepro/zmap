# Multiplayer requirements and measured coverage

The functional multiplayer paths have automated coverage. The entire nonfunctional target matrix in `specs.md` is **not yet qualified**. Passing a local browser test is not a physical-phone or WAN percentile claim.

Run `npm test` for service, protocol, persistence and simulation tests, then `npm run test:e2e` for real browser journeys. The network test is `tests/browser/network.spec.ts`, using `tests/helpers/network-proxy.ts`; its latest sample is `docs/evidence/network-sample.json`. Browser tests use ports 5174/8788/8790 and disposable test-room data, independently of the user's live 5173 session.

Avatar Studio has its own unit, browser and package-consumer tests. The hub now uses its prepared factories, so the root browser suite also exercises that integration. Both suites run in CI. CI on a desktop runner is useful regression evidence, not a substitute for the remaining device and full-room matrix above.

## Field action extension

The three-tool action catalog adds deterministic object claims, reflected toys, real player impulses, per-tool cooldowns, geometric obstruction checks and bounded state. Real sockets cover 20 capable peers, the 64-command pending limit, checkpoint draining and unacknowledged replay after host loss. Three rendered browsers exercise a winch pass into a panel and a ground pulse affecting another player under the same shaped transport described above; late join and host handoff retain valid state.

The [120-second simulation sample](evidence/actions/core-load.json) uses 20 actors and five toys: p95 core step 0.128 ms, largest serialized state 16,816 bytes and a maximum of 32 retained events. This is CPU simulation evidence, not a 20-avatar rendering result. [Browser action evidence](evidence/actions/multiplayer.json) records a single recovery observation and real accepted events, without claiming a recovery percentile. See the [field action API and limits](field-tools.md).

## Movement and rendering regression

`tests/browser/synchronization.spec.ts` reproduces the reported rubberband with a visible host whose animation callbacks run at one frame per second. The corrected host withdraws eligibility and a responsive peer continues shared simulation. A separate journey drives Sam through actual keyboard events, verifies authoritative displacement and retention after release, and repeats movement after host promotion. Render-transform sampling checks that both host and local-peer display positions advance between the 30 Hz simulation ticks. Raw observations are in `docs/evidence/synchronization/`.

`tests/browser/navigation.spec.ts` verifies actual click/tap movement, remote persistence, redirection and Escape; terrain routes around a wall and onto the ramp/bridge; joystick capture cancellation; and portrait layout. Pure navigation tests also execute planned paths through ordinary movement physics and reject unsupported gaps, blocked placements and excessive work.

Ball-to-ball tests cover shared substeps, momentum/energy, extreme authored masses, piles, high speeds and terrain separation. Wake Driver tests require a real supported landing before a pulse and replay checkpoints from every physical action phase. These strengthen functional and bounded-state coverage; the outstanding full-room phone, thermal and network percentile qualifications above remain unchanged.
